# Сценарий защиты: 5–7 минут

## Подготовка

Откройте сайт на компьютере и телефоне. Получите у команды администратора и
обычного пользователя; не выводите их пароли на общий экран. Проверьте
`/api/v1/health`: `status=ok`, `database=ok`. В Telegram откройте группу `keeper`.
Используйте явно названные демонстрационные платежи, не реальные реквизиты.

## 1. Проблема — 30 секунд

«У команды повторяются платежи за аренду, подписки и инфраструктуру. В чатах
теряются сроки и отметки оплаты. Ритм объединяет календарь, историю и напоминания».

## 2. Главная и устройства — 1 минута

Покажите календарь и переключение месяца, просрочки и отдельные сводки валют.
Откройте тот же адрес на телефоне: установка приложения не требуется.
Подчеркните: данные общие, поскольку оба устройства обращаются к одному API/MySQL.

## 3. Создание платежа и бот — 2 минуты

Под администратором создайте «Демо: подписка» с суммой и сроком через два дня.
Покажите созданный период. Дождитесь цикла планировщика или вызовите ручной
прогон через авторизованный API `POST /api/v1/reminders/run`.
Покажите сообщение в группе и кнопку «Оплачено».

Если Telegram временно недоступен, покажите состояние API и журнал ошибок;
не выдавайте имитацию сообщения за реальную доставку.

## 4. Оплата, история, роли — 1–2 минуты

Отметьте период оплаченным. Обновите сайт, откройте историю, сравните плановую
и фактическую даты. Войдите обычным пользователем: он может отмечать оплату,
но не управлять регулярными платежами и пользователями. Права проверяет сервер.
Прекратите демонстрационный регулярный платёж и покажите сохранённую историю.

## 5. Архитектура и доказательства — 1 минута

Откройте схему в ARCHITECTURE.md: Flutter → Nginx → FastAPI → MySQL, а
планировщик связан с Telegram Bot API. Покажите Swagger и результаты тестов.
Объясните различие шаблона платежа и его месячного периода.

## Что честно сказать об ограничениях

Сервис учитывает платежи, но не проводит банковские операции. Для Web нужен
интернет. Обновление UI не является real-time push. Сейчас демонстрационный
IP работает по HTTP; для эксплуатации нужны HTTPS и обновление опубликованных
ранее секретов. Масштабирование планировщика на несколько API-процессов ещё
не реализовано.
